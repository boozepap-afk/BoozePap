# Production Worker

Cloudflare Workers Builds must deploy this repository's `main` branch to
the existing Worker **boozepap**. Use `npm ci` for dependency installation
and `npx wrangler deploy` (or `npm run deploy:cloudflare`) for deployment.
Wrangler runs the OpenNext build defined in `wrangler.jsonc` automatically.

The `WORKER_SELF_REFERENCE` service must also be **boozepap**. A reference
to `app-name` is an autogenerated placeholder and fails with error 10143.
The committed configuration avoids generating a new deployment setup on
every build. Existing dashboard variables and secrets are preserved.

Set these Cloudflare **Build variables** from the same Supabase project
that contains the production products:

- `NEXT_PUBLIC_SUPABASE_URL`
- `NEXT_PUBLIC_SUPABASE_ANON_KEY` or `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`

Also retain them in the Worker's runtime variables. The public browser
configuration is compiled into the JavaScript bundle, so runtime-only
settings are insufficient. Never use a service-role key for these fields.
The build log must not report missing Supabase configuration.

Validate a prepared Worker bundle without uploading with
`npx wrangler deploy --dry-run`. After deployment, confirm that product
prices match Supabase and that `scripts/test-live-prices.mjs` passes with
`node --experimental-strip-types scripts/test-live-prices.mjs` locally.
Do not rerun the price increase migration to refresh the website.
